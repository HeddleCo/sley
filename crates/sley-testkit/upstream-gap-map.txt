================================================================================
SLEY UPSTREAM GAP MAP (foundational subset)
================================================================================

Source oracle : upstream git v2.54.0 t/*.sh suite, run against the Sley binary
                via crates/sley-testkit/scripts/run-upstream-tests.sh.
Hash algo     : sha1 (GIT_TEST_DEFAULT_HASH=sha1 — REQUIRED, see "Harness note").
Pass/total    : counts are TAP assertions actually executed (ok / ok+not-ok).
                The TAP plan total is noted separately where the script aborts
                or hangs before finishing.

Harness env   : use the SLEY_* environment variables documented by the runner.

This is the curated, themed companion to the auto-generated upstream-report.txt
(which lists every failing "not ok N - <title>" verbatim). Use this file to
decide which command-hardening agents to spawn; use upstream-report.txt for the
raw per-assertion detail of a specific run.

Classification legend:
  [CLI]    sley-cli layer: flag/option parsing, output formatting, error text,
           process exit codes, alias/-c handling, repo discovery.
  [REV]    sley-rev layer: revision/object-name resolution (<rev>:<path>, ^{},
           :/search, --short abbreviation, --since pass-through).
  [FMT]    sley-formats / sley-odb: config file parser/writer, object structure
           validation, attribute/filter application.
  [REFS]   sley-refs: ref name validation, d/f conflicts, reflog.
  [WT]     sley-worktree: working-tree walk (ls-files), checkout, worktree add.
  [AUX]    unimplemented auxiliary command surfaced as a dependency
           (fast-import, clone/fetch, submodule, repack, rev-list filters).

--------------------------------------------------------------------------------
CRITICAL: rev-parse --short=N infinite loop  [REV]
--------------------------------------------------------------------------------
`git rev-parse --short=N <rev>` spins at 100% CPU forever when N >= the full
hash hex length (40 for sha1, 64 for sha256). --short=40, --short=41, --short=100
all hang; --short=39 is fine. Upstream clamps to the full hash length and just
prints the whole oid. This single hang aborts t1500 at test 81 and, without a
timeout, orphans a spinning process. The harness now caps each script (Perl
alarm fallback that kills the child's process group), so the batch survives, but
the bug itself must be fixed in the abbreviation/unique-prefix search (clamp the
requested length to the hash length + add a loop-termination guard).
Minimal repro:
    git init r && cd r && git commit --allow-empty -m x
    git rev-parse --short=40 HEAD     # hangs

--------------------------------------------------------------------------------
CROSS-CUTTING THEMES (fix once, many scripts improve)
--------------------------------------------------------------------------------

T1. Usage errors must exit 129, not 1.  [CLI]
    Sley detects bad option combos and prints good messages, but exits 1.
    Upstream uses exit code 129 for usage errors; tests assert
    `test_expect_code 129`. This is the dominant ls-tree failure (8 of 9) and a
    large share of cat-file's ~56 "usage:" failures.
    Examples: `ls-tree --long --name-only`, `cat-file -e -p`, `cat-file -p`
    (no object). Affects: ls-tree, cat-file, hash-object, likely all commands.

T2. Aliases and `-c` overrides are not expanded.  [CLI]
    `git aliasedinit` (alias for init) -> "unsupported command aliasedinit".
    Affects: init (aliasedinit, script), config ("unsupported command
    hello-world/checkconfig/CamelCased/x"). Alias expansion from [alias] config
    is unimplemented.

T3. config writer lowercases names and drops case.  [CLI]/[FMT]
    Writing `Section.Movie` produces `[section] movie = ...`; git preserves the
    variable name case as typed (`Movie`) and the existing section-header case
    (`[Sections]`, not `[sections]`). Lookups are case-insensitive (correct) but
    WRITES must preserve case. Cascades into nearly every config write/compare
    test. Examples: "mixed case", "similar section", "uppercase section".

T4. checkout -B / -b / --orphan fails on clean repos.  [WT]
    `git checkout -B main` (and `-b`, `--orphan`) -> "transaction failed:
    checkout requires a clean working tree" even when the tree is clean.
    Breaks setup steps in t1500 (test 1) and t1401 (tests 14, 15), cascading.

--------------------------------------------------------------------------------
HARNESS NOTE (why GIT_TEST_DEFAULT_HASH matters)
--------------------------------------------------------------------------------
This checkout's GIT-BUILD-OPTIONS omits GIT_TEST_BUILTIN_HASH. Upstream
test-lib's test_detect_hash then leaves $test_hash_algo empty, so EVERY
`test_oid` lookup aborts the script with "BUG: undefined key '...'", poisoning
otherwise-passing assertions (e.g. hash-object jumped 13->21 ok, cat-file
95->115, config 110->131 once a hash was set). The runner now defaults
GIT_TEST_DEFAULT_HASH=sha1 (override with SLEY_DEFAULT_HASH=sha256). Always
keep this set when interpreting results.

Suggested agent order (impact-first):
  1. rev-parse --short=N hang fix (correctness + unblocks t1500).         [REV]
  2. Usage exit code 129 (T1): ls-tree + cat-file jump immediately.       [CLI]
  3. config writer case preservation (T3) + value-pattern + --comment.    [CLI/FMT]
  4. config `list/get/set/unset` subcommands (unlocks ~half of t1300).    [CLI]
  5. ls-files --others symlink + embedded-.git handling.                  [WT]
  6. checkout -B/-b/--orphan clean-tree bug (T4): unblocks several setups.[WT]
  7. symbolic-ref ref-name validation + error text + d/f conflicts.       [REFS]
  8. alias / -c expansion (T2).                                           [CLI]
